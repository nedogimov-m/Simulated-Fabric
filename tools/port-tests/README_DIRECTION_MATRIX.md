# Проверка направлений Fabric 26.3

Матрицы запускают настоящие production JAR Simulated, Aeronautics, Offroad, Sable и готовый Create в dedicated server. Они размещают реальные блоки, приводят их настоящим Create motor, меняют сигнал и читают фактическое состояние сети и владельцев. Подмена кинетического решателя тестовой моделью не используется.

| Группа | Проверяемые условия |
|---|---|
| Directional gearshift | 12 ориентаций, оба входа, −64/0/+64 RPM, четыре состояния двух сигналов, все направленные переходы между ними, смена источника и загрузка мира |
| Analog transmission | Три оси, физический и дополнительный каналы, геометрия зацепления, все 16 уровней настоящего компаратора, реверс, смена источника, отключение, предел скорости и oversaturation при холодном запуске и загрузке |
| Borehead bearing | 12 ориентаций, оба источника, совместимые упорядоченные пары подшипников, реверс/стоп, настоящая сборка/вращение/разборка ротора с сохранением груза и загрузка мира |
| Torsion spring | Шесть направлений, оба владельца каналов, −64/0/+64 RPM, ограниченное заведение/реверс, удержание сигналом и освобождение, независимость выходного канала и загрузка мира |
| Swivel bearing | Шесть направлений, привод через платформу и зубчатые соединения, реверс и вторичный канал, блокировка, настоящий физический joint, перепривязка платформы и загрузка мира |

Первый процесс сохраняет мир и штатно завершается. Фаза `restore` запускается в новой JVM с тем же миром; проверяется настоящий восстановленный владелец, а не созданная тестом копия NBT. Для Swivel используется 20 TPS с настоящей физикой. Остальные матрицы допускают ускорение серверных тиков.

Каждая принятая строка содержит устойчивый ID, фазу, исходный SHA256 `inputs.json` и наблюдения. Повторный запуск пропускает принятые ID. После ошибки продолжаются только незавершённые случаи. Смена helper не переписывает входные хеши прежних строк; старые manifests и версии helper сохраняются отдельно. Если меняется проверяемая production-ответственность, область прежнего результата сначала пересматривается.

Пример запуска из корня проекта (все пять `--mod` должны указывать на production JAR из отчёта):

```sh
JAVA_HOME=/opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home \
python3 tools/run_packaged_smoke.py \
  --name direction-gearshift --side server \
  --direction-checks gearshift --direction-phase initial \
  --mod ../26_3_porting/build/libs/create-fabric-6.0.10-port.2+mc26.3.jar \
  --mod ports/sable/build/libs/sable-fabric-26.3-2.0.6-port.1+mc26.3.jar \
  --mod simulated/fabric/build/libs/simulated-fabric-26.3-1.3.2-port.1+mc26.3.jar \
  --mod aeronautics/fabric/build/libs/aeronautics-fabric-26.3-1.3.2-port.1+mc26.3.jar \
  --mod offroad/fabric/build/libs/offroad-fabric-26.3-1.3.2-port.1+mc26.3.jar
```

Для загрузки меняется только `--direction-phase restore`; имя и мир остаются прежними. Swivel требует `--direction-tick-rate 20`.

Сырые журналы и история попыток: `build/porting/packaged-smoke/direction-*/server/`. Принятые неизменяемые снимки: `build/porting/verified-direction-*/`. Итоговые числа и точные границы публикуются в `PORTING_TESTS.md` и `build/porting/direction-adapter-audit/`.

Число строк включает отдельно записанные этапы одного сценария: например, холодный запуск, переключение и восстановление. Оно не равно числу независимых конструкций и не означает перебор всех возможных сетей или необязательных модов.
